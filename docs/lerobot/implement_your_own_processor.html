实现您自己的机器人处理器

在本教程中，您将学习如何实现自己的机器人处理器（Robot Processor）。本教程首先探讨了对自定义处理器的需求，然后以 NormalizerProcessorStep 为例，讲解如何实现、配置和序列化处理器。最后，它列出了 LeRobot 随附的所有辅助处理器。

为什么需要自定义处理器？

在大多数情况下，当从传感器读取原始数据或当模型输出动作时，您需要对这些数据进行处理，使其与您的目标系统兼容。例如，常见的需求是归一化数据范围，使其适用于神经网络。

LeRobot 的 NormalizerProcessorStep 负责处理这项关键任务

# Input: raw joint positions in [0, 180] degrees
raw_action = torch.tensor([90.0, 45.0, 135.0])

# After processing: normalized to [-1, 1] range for model training
normalizer = NormalizerProcessorStep(features=features, norm_map=norm_map, stats=dataset_stats)
normalized_result = normalizer(transition)
# ...

其他常见的处理需求包括：

  • 设备放置：在 CPU/GPU 之间移动张量并转换数据类型
  • 格式转换：在不同的数据结构之间进行转换
  • 批处理：为了模型兼容性添加/移除批处理维度
  • 安全约束：对机器人指令应用限制
# Example pipeline combining multiple processors
pipeline = PolicyProcessorPipeline([
    RenameObservationsProcessorStep(rename_map={}),
    AddBatchDimensionProcessorStep(),
    NormalizerProcessorStep(features=features, stats=stats),
    DeviceProcessorStep(device="cuda"),
    # ...
])

LeRobot 提供了一种管道（pipeline）机制，用于实现输入数据和输出动作的处理步骤序列，从而能够轻松按正确的顺序组合这些转换，以获得最佳性能。

如何实现您自己的处理器？

我们将使用 NormalizerProcessorStep 作为主要示例，因为它演示了您通常需要的核心处理器模式，包括状态管理、配置序列化和张量处理。

准备解决您的问题所需的处理步骤序列。处理器步骤是一个实现了以下方法的类：

  • __call__：实现输入转移的处理步骤。
  • get_config：获取处理器步骤的配置。
  • state_dict：获取处理器步骤的状态。
  • load_state_dict：加载处理器步骤的状态。
  • reset：重置处理器步骤的状态。
  • feature_contract：显示处理器步骤期间对特征空间的修改。

实现 __call__ 方法

__call__ 方法是处理器步骤的核心。它接收一个 EnvTransition 并返回修改后的 EnvTransition。以下是 NormalizerProcessorStep 的工作原理：

@dataclass
@ProcessorStepRegistry.register("normalizer_processor")
class NormalizerProcessorStep(ProcessorStep):
    """Normalize observations/actions using dataset statistics."""

    features: dict[str, PolicyFeature]
    norm_map: dict[FeatureType, NormalizationMode]
    stats: dict[str, dict[str, Any]] | None = None
    eps: float = 1e-8
    _tensor_stats: dict = field(default_factory=dict, init=False, repr=False)

    def __post_init__(self):
        """Convert stats to tensors for efficient computation."""
        self.stats = self.stats or {}
        self._tensor_stats = to_tensor(self.stats, device=self.device, dtype=torch.float32)

    def __call__(self, transition: EnvTransition) -> EnvTransition:
        new_transition = transition.copy()
        # Normalize observations
        # ...
        # Normalize action
        # ...
        return new_transition

有关完整详情，请参阅 src/lerobot/processor/normalize_processor.py 中的完整实现。

核心原则：

  • 始终使用 transition.copy() 以避免副作用
  • 一致地处理观察和动作
  • 将配置与状态分离：get_config() 返回可 JSON 序列化的参数，state_dict() 返回张量
  • 在 __post_init__() 中将统计数据转换为张量，以便进行高效计算

配置与状态管理

处理器通过三种方法支持序列化，这些方法将配置与张量状态分离。NormalizerProcessorStep 完美地展示了这一点——它在其状态中携带数据集统计信息（张量），在其配置中携带超参数。

# Continuing the NormalizerProcessorStep example...

def get_config(self) -> dict[str, Any]:
    """JSON-serializable configuration (no tensors)."""
    return {
        "eps": self.eps,
        "features": {k: {"type": v.type.value, "shape": v.shape} for k, v in self.features.items()},
        "norm_map": {ft.value: nm.value for ft, nm in self.norm_map.items()},
        # ...
    }

def state_dict(self) -> dict[str, torch.Tensor]:
    """Tensor state only (e.g., dataset statistics)."""
    flat: dict[str, torch.Tensor] = {}
    for key, sub in self._tensor_stats.items():
        for stat_name, tensor in sub.items():
            flat[f"{key}.{stat_name}"] = tensor.cpu()  # Always save to CPU
    return flat

def load_state_dict(self, state: dict[str, torch.Tensor]) -> None:
    """Restore tensor state at runtime."""
    self._tensor_stats.clear()
    for flat_key, tensor in state.items():
        key, stat_name = flat_key.rsplit(".", 1)
        # Load to processor's configured device
        self._tensor_stats.setdefault(key, {})[stat_name] = tensor.to(
            dtype=torch.float32, device=self.device
        )
        # ...

用法

# Save (e.g., inside a policy)
config = normalizer.get_config()
tensors = normalizer.state_dict()

# Restore (e.g., loading a pretrained policy)
new_normalizer = NormalizerProcessorStep(**config)
new_normalizer.load_state_dict(tensors)
# Now new_normalizer has the same stats and configuration

特征转换

transform_features 方法定义了您的处理器如何转换特征名称和形状。这对于策略配置和调试至关重要。

对于 NormalizerProcessorStep，特征通常保持不变，因为归一化不会改变键或形状

def transform_features(self, features: dict[PipelineFeatureType, dict[str, PolicyFeature]]) -> dict[PipelineFeatureType, dict[str, PolicyFeature]]:
    """Normalization preserves all feature definitions."""
    return features  # No changes to feature structure
    # ...

当您的处理器重命名数据或重塑数据形状时，请实现此方法以反映下游组件的映射。例如，一个简单的重命名处理器：

def transform_features(self, features: dict[str, PolicyFeature]) -> dict[str, PolicyFeature]:
    # Simple renaming
    if "pixels" in features:
        features["observation.image"] = features.pop("pixels")

    # Pattern-based renaming
    for key in list(features.keys()):
        if key.startswith("env_state."):
            suffix = key[len("env_state."):]
            features[f"observation.{suffix}"] = features.pop(key)
            # ...

    return features

核心原则：

  • 使用 features.pop(old_key) 移除并获取旧特征
  • 使用 features[new_key] = old_feature 添加重命名后的特征
  • 始终返回修改后的特征字典
  • 在 docstring 中清晰地记录转换

使用覆盖 (overrides)

您可以在加载时使用 overrides 覆盖步骤参数。这对于不可序列化的对象或特定地点的设置非常方便。它在策略工厂和 DataProcessorPipeline.from_pretrained(...) 中均可使用。

基础模型适配：当使用基础预训练策略时，这特别有用，因为您很少能获得原始的训练统计数据。您可以注入自己的数据集统计数据，以使归一化器适配您的特定机器人或环境数据。

示例：在机器人的策略评估期间，覆盖设备和重命名映射。使用此功能在仅限 CPU 的机器人上运行在 CUDA 上训练的策略，或者当机器人使用的名称与数据集不同时重映射摄像头键。

直接与 from_pretrained 配合使用

from lerobot.processor import RobotProcessorPipeline

# Load a foundational policy trained on diverse robot data
# but adapt normalization to your specific robot/environment
new_stats = LeRobotDataset(repo_id="username/my-dataset").meta.stats
processor = RobotProcessorPipeline.from_pretrained(
    "huggingface/foundational-robot-policy",  # Pretrained foundation model

        "normalizer_processor": {"stats": new_stats},     # Inject your robot's statistics
        "device_processor": {"device": "cuda:0"},         # registry name for registered steps
        "rename_processor": {"rename_map": robot_key_map}, # Map your robot's observation keys
        # ...
    },
)

最佳实践

基于对所有 LeRobot 处理器实现的分析，以下是关键模式和实践：

1. 安全数据处理

始终创建输入数据的副本，以避免意外的副作用。使用 transition.copy() 和 observation.copy()，而不是原位（in-place）修改数据。这可以防止您的处理器意外影响管道中的其他组件。

在处理之前检查所需数据，并优雅地处理缺失数据。如果您的处理器需要某些键（例如图像处理所需的 "pixels"），请先验证它们是否存在。对于可选数据，使用 transition.get() 等安全访问模式并适当处理 None 值。

当数据验证失败时，提供清晰且可操作的错误消息，帮助用户理解出了什么问题以及如何修复。

2. 选择合适的基类

LeRobot 提供了专门的基类，可减少样板代码并确保一致性。当您只需要修改观察值时，使用 ObservationProcessorStep；对于仅处理动作的操作，使用 ActionProcessorStep；专门针对基于字典的机器人动作，使用 RobotActionProcessorStep。

仅在需要完全控制整个转移（transition）或同时处理多个转移组件时，才直接从 ProcessorStep 继承。专门的基类会为您处理转移管理并提供类型安全。

3. 注册与命名

使用 @ProcessorStepRegistry.register() 注册具有描述性的、带命名空间的名称。使用组织前缀，如 "robotics_lab/safety_clipper" 或 "acme_corp/vision_enhancer"，以避免命名冲突。避免使用 "processor" 或 "step" 等可能与其他实现冲突的通用名称。

良好的注册使您的处理器可被发现，并在保存和加载管道时实现清晰的序列化/反序列化。

4. 状态管理模式

区分配置参数（可 JSON 序列化的值）和内部状态（张量、缓冲区）。对于不应出现在构造函数或字符串表示形式中的内部状态，使用带 init=False, repr=False 的 dataclass 字段。

实现 reset() 方法以在两集（episodes）之间清除内部状态。这对于随着时间积累数据的有状态处理器（如移动平均或时间滤波器）至关重要。

记住，get_config() 应仅返回可 JSON 序列化的配置，而 state_dict() 分别处理张量状态。

5. 输入验证与错误处理

在处理之前验证输入类型和形状。检查 dtype 和维度等张量属性，以确保与您的算法兼容。对于机器人动作，请验证所需的姿态组件或关节值是否存在且在预期范围内。

对于不需要处理的边缘情况使用提前返回。提供清晰、具描述性的错误消息，包括预期与实际的数据类型或形状。这使用户调试变得更加容易。

6. 设备与 Dtype 感知

设计您的处理器以自动适配输入张量的设备和数据类型（dtype）。内部张量（如归一化统计量）应匹配输入张量的设备和 dtype，以确保与多 GPU 训练、混合精度和分布式设置兼容。

实现一个 to() 方法，将处理器的内部状态移动到指定的设备。在运行时检查设备/dtype 兼容性，并在需要时自动迁移内部状态。此模式可在不同的硬件配置之间实现无缝操作，无需人工干预。

结论

您现在已经拥有了在 LeRobot 中实现自定义处理器的所有工具！关键步骤如下：

  1. 将您的处理器定义为一个具有所需方法的 dataclass（__call__、get_config、state_dict、load_state_dict、reset、transform_features）
  2. 使用 @ProcessorStepRegistry.register("name") 注册它以提高可发现性
  3. 将其与其他处理步骤一起集成到 DataProcessorPipeline 中
  4. 尽可能使用基类（如 ObservationProcessorStep）来减少样板代码
  5. 实现设备/dtype 感知以支持多 GPU 和混合精度设置

处理器系统被设计为模块化和可组合的，允许您利用简单、专注的组件构建复杂的数据处理管道。无论您是在为训练预处理传感器数据，还是在为机器人执行后处理模型输出，自定义处理器都能为您提供灵活性，以处理您的机器人应用所需的任何数据转换。

稳健处理器的核心原则：

  • 设备/dtype 适配：内部张量应匹配输入张量
  • 清晰的错误消息：帮助用户理解出了什么问题
  • 基类使用：利用专门的基类减少样板代码
  • 特征契约：使用 transform_features() 声明数据结构更改

从简单的开始，彻底测试，并确保您的处理器在不同的硬件配置下都能无缝工作！
